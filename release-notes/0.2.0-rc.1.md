## DiagPermit v0.2.0-rc.1 - Release Candidate

> This is a release candidate intended for public testing before v0.2.0
> stable. It is not a production-stable release.

DiagPermit is an open protocol and local-first developer tool for
consent-driven diagnostic exchange. A requester declares the diagnostic
capabilities it needs, users approve or deny them, collection and configured
privacy transformations happen locally, and the resulting diagnostic package
contains a disclosure receipt and integrity-verifiable manifest.

### Highlights

- Local-first diagnostic workflow - no account, no server, no upload
- Explicit capability consent (required / optional / forbidden)
- Embedded local UI (`diagpermit ui`), loopback-only, no Node.js needed
- Typed collectors (system, runtime, application logs, Docker)
- Privacy transformations with fail-closed behaviour
- Disclosure receipts in every artifact
- Signed-request authenticity (DSSE + Ed25519, local trust policy)
- Integrity verification (`INTEGRITY VERIFIED`)
- No automatic diagnostic upload, ever

### Getting started

Download the binary for your platform, then:

```bash
diagpermit init
diagpermit validate
diagpermit plan
diagpermit collect --yes
diagpermit inspect support-*.diagnostic
diagpermit verify support-*.diagnostic
diagpermit ui
```

Verify the downloaded file against `SHA256SUMS` first.

### Compatibility

- Protocol version: 0.1 (unchanged)
- V0.1 `.diagnostic` artifacts remain readable and verifiable
- All V0.1 CLI commands remain available; the CLI works headless

### Known limitations

- Release binaries are not cryptographically signed; use `SHA256SUMS` and
  the CycloneDX SBOM.
- Docker diagnostics require a running Docker daemon.
- Pattern-based redaction never guarantees complete secret removal; review
  content before sharing.
- No browser-level (Playwright) CI E2E yet; the UI workflow is covered by
  Go API-level security tests.
