# Support

## How to get help

- Bug reports and feature ideas: open a GitHub issue.
- Security problems: follow [SECURITY.md](SECURITY.md) and use private
  vulnerability reporting, not a public issue.
- Protocol discussions: open a GitHub issue.

There is no commercial support tier. The project is maintained by volunteers
in their personal time and does not currently solicit sponsorship.

## What to include in a bug report

- `diagpermit doctor` output.
- OS/architecture and how DiagPermit was installed.
- The exact commands run.
- For artifact problems: `diagpermit verify <artifact>` output.

Never attach real credentials, customer logs, employer data, or an unreviewed
diagnostic package to a public issue.
